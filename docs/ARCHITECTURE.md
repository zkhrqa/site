# Архитектура первой версии

## Решение

Статический React-сайт на TypeScript с Vite и обычным CSS/токенами. Первоначальную основу предоставляет веб-шаблон Product Design `prototype`; TypeScript добавляется с сохранением его поддерживаемой сборки. Приложение планируется в `web/`. Версии зависимостей фиксируются при инициализации, а не предполагаются из этого документа.

В production сервер отдаёт готовые HTML, JavaScript, CSS, изображения и файлы. Node.js нужен на машине сборки; постоянно работающий Node.js, PostgreSQL, Payload CMS и Next.js-сервер для этого объёма не требуются. Следовать актуальным требованиям Product Design к шаблону и упаковке; дополнительный Worker для совместимости шаблона не превращает приложение в серверную систему хранения данных.

Статический хостинг всё равно является сервером раздачи файлов; отказываемся от прикладной серверной части и базы, а не от размещения сайта в интернете.

## План файлов

```text
site/
  AGENTS.md
  docs/
  references/                 исходники и визуальные источники, не публикуются
  web/                        создаётся на этапе реализации
    src/
      content/                уроки, народы, автор, настройки
      components/             общие элементы
      features/map/           карта и выбор остановки
      features/lesson/        страница, проигрывание этапов, задания
      features/progress/      хранение, экспорт и импорт
      styles/                 токены, типографика, адаптация, печать
    public/
      assets/                 подготовленные иллюстрации и шрифты
      materials/              проверенные PDF/DOCX для скачивания
```

При bootstrap в `web/` стандартный шаблон создаёт собственные файлы и команды. Проверить их перед изменением; не предполагать, что каталог статического выпуска обязательно называется `dist/` — шаблон может выдавать `dist/client/`.

## Данные урока

Один объект урока содержит:

- Стабильный `id`, независимый от номера/заголовка; например `lesson-01`.
- Порядковый номер, slug, короткое и полное названия, класс, статус `draft`/`published`.
- Ссылку на народ и героя; имя, реплику и путь к иллюстрации героя.
- Цель, ожидаемые результаты, культурный контекст и источник материала.
- Последовательность типизированных блоков; у каждого собственный стабильный ID.
- Ссылки на материалы с форматом, названием и назначением.
- Идентификаторы отметок на карте. Народ, урок и точка — отдельные сущности.

Общая оболочка урока отображает блок по `type`, например `story`, `rule`, `choice`, `matching`, `sequence`, `highlight`, `punctuation`, `creative`, `reflection`. Данные и проверка ответа не зашиваются в JSX конкретной страницы. Путь картинки или файла не принимается из пользовательского импорта прогресса.

Результат автоматической проверки возможен для заранее заданных ответов. Для разных допустимых решений нужен явный список/правило, проверенное педагогом. Не использовать точное сравнение произвольного творческого текста с одной эталонной строкой.

Первым способом хранения контента будут проверяемые TypeScript-объекты. Можно перейти к JSON/Markdown, если это действительно упростит редактирование; не добавлять несколько параллельных форматов без необходимости.

## Прогресс

Одна локальная коллекция завершённых уроков для одного браузера. Не собирать имена учеников, email и индивидуальные оценки. Несколько классов и автоматическая синхронизация не входят в первую версию.

Контракт экспорта и localStorage:

```json
{
  "format": "album-druzhby-progress",
  "schemaVersion": 1,
  "completedLessonIds": ["lesson-01", "lesson-02"]
}
```

Ключ localStorage: `album-druzhby:progress`. Версия находится внутри данных. Не менять ключ при каждом выпуске сайта. Статистика на карте вычисляется по опубликованным урокам, а не хранится отдельным счётчиком. Не включать в файл импортируемую разметку или ссылки.

Сценарии:

1. При запуске безопасно прочитать, разобрать и проверить сохранение. Ошибка не ломает страницу.
2. После «Мы познакомились»/отмены обновить память приложения и попытаться записать данные.
3. При неудачной записи показать короткое сообщение «Отметка действует до закрытия страницы. Сохраните копию путешествия». Не показывать ложное «Сохранено».
4. Экспорт создаёт JSON из текущих отметок, включая те, которые пока не удалось записать в браузер.
5. Импорт принимает только небольшой JSON (предлагаемый предел 100 КБ), проверяет формат, поддерживаемую версию, типы, ограничение числа ID и удаляет дубликаты. Неизвестные ID отклоняются с понятным сообщением без изменения текущих отметок; это не позволяет молча потерять отметки из более новой версии сайта.
6. Режим импорта по умолчанию — объединить с текущими отметками. Полный сброс — отдельное подтверждаемое действие. Восстановление не проигрывает массовую анимацию.
7. Изменение заголовка/порядка уроков не меняет его ID. При развитии формата добавлять явные миграции; более новую неподдерживаемую версию не перезаписывать молча.
8. Несколько вкладок одного адреса могут обновлять представление через `storage` event. Слияние конфликтов облачной системы не требуется.

Сохранение привязано к origin: протокол, домен и порт. Перед сменой домена пользователь экспортирует файл. Неделя отсутствия сама по себе не должна удалять прогресс; очистка браузером/пользователем и приватный режим могут его убрать. Общий компьютер разделяет одно путешествие между посетителями.

На странице управления дать простое объяснение «Отметки сохраняются в этом браузере. Чтобы перенести их, сохраните файл путешествия». При недоступном хранилище читать и выполнять задания всё равно можно.

## Карта

Рисованная подложка и DOM-отметки используют одну систему координат. Возможны координаты в процентах исходного полотна или геопроекция; выбрать один подход и записать его после проверки реальной карты. Не брать координаты из художественного скриншота.

Масштабирование/перемещение воздействуют на общий контейнер подложки и маркеров. Подписи и панель деталей не должны выходить за экран. Список остановок работает независимо от масштаба. Если точка относится к нескольким урокам, открывается список доступных знакомств.

Для будущих 20 точек проверить плотные группы, клавиатуру и касания. Будущие уроки размещать только по реальному списку пользователя. Данные тестового набора не публиковать как факты.

## Добавление урока без админки

1. Сохранить исходники вне публичных файлов.
2. Заполнить объект урока и использовать существующие блоки.
3. Подготовить изображения и проверенные PDF/DOCX.
4. Добавить запись в каталог и реальные координаты/места знакомства.
5. Выполнить проверку данных: уникальные ID, ссылки, обязательные поля, допустимые ответы.
6. Собрать, проверить в браузере и опубликовать обновление.

Пользователь редактирует материалы в Word; преобразование в интерактивные блоки остаётся отдельной работой. Защищённая веб-админка без серверной записи не обещается. Локальный редактор с экспортом файла можно рассмотреть позже, только если он нужен.

## Размещение на REG.RU

Домен и статический тариф с HTTPS. На хостинг отправляется только клиентская сборка и подготовленные публичные файлы. Исходные DOC/DOCX, черновики, документы проекта и референсы экранов автоматически не публикуются.

Человекочитаемые адреса уроков требуют SPA fallback на `index.html`; проверить поддержку тарифа и прямой вход по URL. Если такой настройки нет, выбрать hash-навигацию, не создавая прикладной сервер ради маршрутизации. Базовый путь, загрузку ресурсов и ссылки на файлы проверить при публикации в корне или подкаталоге.

Первая версия не обещает полноценную работу без интернета. Автономное использование обеспечивается скачиваемыми материалами; PWA-кэширование обсуждается отдельно. Платный VPS из прежнего расчёта не является обязательным для статического выпуска.

При росте можно вынести контент в CMS и заменить слой прогресса на серверный, сохранив стабильные ID и компоненты. Не строить эту будущую инфраструктуру заранее.

## Решения первого маршрута

Реализовано в `web/`: React 19 + TypeScript + Vite. Адреса `#/`, `#/lesson/1`, `#/lesson/1/activity`, `#/map`, `#/lessons`, `#/about`; проектор — `#/lesson/1/activity?projector`. Серверное перенаправление маршрутов не нужно. Слой прогресса — `src/features/progress.ts`, формат v1, ключ `album-druzhby:progress`, опубликованный ID `lesson-01`.

Повреждённые/неподдерживаемые существующие данные не перезаписываются обычным завершением: новое путешествие остаётся в памяти и экспортируется. Явный сброс позволяет заменить прежнее сохранение. Сбой записи показан пользователю. Конкурирующие одновременные изменения в разных вкладках не сливаются транзакционно; `storage` event обновляет представление последним сохранением.

Карта — путь, вычисленный из Natural Earth 50m в antimeridian-aware конической проекции D3. В браузер передаётся готовый путь; D3 в runtime не загружается. Акварельное заполнение декоративное и не изображает физическую карту. По последнему решению пользователя добавлены 20 условных точек-загадок, включая одну для знакомства с русской культурой. Они не обозначают исключительные территории расселения. Точная привязка уточняется при наполнении. Масштабирование, перемещение, группировка и список остановок реализованы.

Карта загружается отдельным JS/CSS-модулем через React.lazy. Общая географическая основа и JSX карты остаются одними; `journey-stops.ts` задаёт 20 стабильных ID и условные координаты, `published-lessons.ts` подключает только реальные опубликованные уроки. Карточка получает сведения из реестра, а progress валидирует ID того же реестра. Подключение нового урока не создаёт новую карту. Модель сгруппированных точек использует экранные расстояния: после масштабирования пересчитывает группы, ни одна остановка не исчезает из данных.
