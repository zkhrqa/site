# Урок Айдара перед вёрсткой

Статус на 3 ноября 2026 года: подготовлены три взаимосвязанных визуальных предложения. Они продолжают выбранный стиль главной «Альбом дружбы»; выбор общей стилистики повторно не проводится. Принятие этих экранов пользователем ещё не зафиксировано.

Содержание реализации определяется документами урока, а не картинками. Все три визуальных предложения показывают компоновку; тексты интерфейса и упражнений перед переносом сверяются с исходниками. Визуальное одобрение изображения не разрешает содержательные расхождения.

## Визуальные предложения

- [Начало урока и первое задание](../references/design/aydar-lesson-desktop-proposal.png) — настольная страница.
- [Задание с объяснением правильного ответа](../references/design/aydar-activity-projector-proposal.png) — режим для проектора.
- [Задание с выбранным, но ещё не проверенным ответом](../references/design/aydar-activity-mobile-proposal.png) — мобильная компоновка.

Все три созданы встроенным Image Gen с прикреплённой выбранной главной как визуальным источником. Промпты сохранены отдельно: [страница](../references/design/prompts/aydar-intro.txt), [проектор](../references/design/prompts/aydar-activity-projector.txt), [телефон](../references/design/prompts/aydar-activity-mobile.txt). Это не разметка, браузерная проверка или доказательство готовности PDF.

## Смысл урока

Ребёнок учится отличать повествование, описание и рассуждение, находить подтверждение в тексте и составлять свой небольшой текст. Айдар восстанавливает семейную книгу историй. Источники: [технологическая карта](../references/lessons/lesson-02-teacher.doc) и [рабочий лист](../references/lessons/lesson-02-worksheet.docx).

Художественная идея: перепутанные страницы становятся понятными, когда ребёнок возвращает каждой её вопрос: «Что произошло?», «Какой?», «Почему?». Упражнение не заменяет чтение красивой иллюстрацией: текст и аргумент выбора остаются центральными.

## Сценарий

1. Открыть урок из каталога/карты.
2. Познакомиться с Айдаром и целью занятия.
3. Рассмотреть три вопроса и примеры типов текста.
4. Определить тип трёх коротких текстов с объяснением по словам-подсказкам.
5. Создать свою страницу книги на бумаге или устно по плану.
6. Выполнить самооценку и по решению учителя отметить знакомство.

Номер «Страница 1 из 3» обозначает три текста конкретного упражнения, а не весь урок. Одно правильное решение не означает завершение занятия. Кнопка «Мы познакомились» доступна учителю независимо от баллов, поскольку часть работы проходит на бумаге.

## Данные упражнения

| Страница | Исходный текст | Ожидаемый тип | Основание |
| --- | --- | --- | --- |
| 1 | Айдар пришёл домой, достал цветную бумагу и сделал открытку для бабушки. | Повествование | Последовательность действий: пришёл, достал, сделал |
| 2 | Открытка яркая, прямоугольная, украшена узором из плавных линий. | Описание | Перечислены признаки открытки |
| 3 | Я считаю, что нужно беречь семейные истории, потому что они хранят память о близких. Поэтому стоит слушать рассказы старших. | Рассуждение | Есть мысль, объяснение и вывод |

Источник этих трёх текстов — рабочий лист урока 2, задание 2 «Разложи страницы по местам», пункты А–В. Данные едины для настольного, мобильного и проекторного представления. Дополнительные задания технологической карты или рабочего листа переносятся как отдельные блоки с собственными ссылками на источник.

Для проекторного визуального предложения использован другой реальный пример из технологической карты: «Утром Айдар помог бабушке приготовить угощение. Потом он украсил коробку узором и отнёс её к праздничному столу». Для первой реализации единый рабочий набор — три текста из таблицы выше во всех режимах. Проекторное представление сохраняет показанную композицию и объясняет действия «пришёл», «достал», «сделал» для первого текста. Выделение «Утром» и «Потом» в картинке — пример визуального приёма для другого исходного текста, а не отдельная версия содержания урока.

## Состояния интерфейса

| Состояние | Представление и действие |
| --- | --- |
| Ответ не выбран | Три подписанных варианта; нажатие «Проверить» сообщает «Сначала выберите тип текста» без перехода |
| Ответ выбран | Один вариант отмечен формой/значком и цветом; его можно изменить |
| Ответ верный | «Верно! Это повествование» и короткое объяснение по конкретному тексту; доступна «Следующая страница» |
| Ответ неверный | «Попробуй ещё раз. Текст рассказывает о событиях или перечисляет признаки?»; выбор можно изменить без штрафа |
| Подсказка | Раскрыть вопрос, который помогает распознать тип; не закрывать сам текст |
| Три текста закончены | Перейти к творческой странице и рефлексии; никакой автоматической отметки по одному упражнению |
| Знакомство отмечено | Короткая наклейка, доступная отмена; при успешной записи отметка переживает обновление страницы |
| Браузер не сохраняет | Содержание работает; честное уведомление и экспорт текущего путешествия |

Клавиатура и нажатия обязательны; drag-and-drop не нужен для классификации. Слова-подсказки выделяются только в момент объяснения/подсказки, если педагог не выберет другой сценарий. Текст остаётся читаемым без движения, фон во время задания неподвижен.

## Образ и графика

Временный образ Айдара: школьник около 9 лет, короткие тёмно-каштановые волосы, оливковый джемпер поверх светлой рубашки, бордово-коричневая семейная книга. Это индивидуальный художественный герой, не модель внешности всего народа. Костюмные стереотипы и неподтверждённые орнаменты не используются.

Нужные отдельные активы: Айдар с книгой, сцена с младшей сестрой за столом и страницами, небольшая иллюстрация открытки/бумаги, книжная подложка, общая фактура и рябина. Шрифты и географическая основа относятся к общему комплекту. Скриншоты не вырезаются на замену самостоятельным изображениям.

Сцена с сестрой и детали открытки подготавливаются после выбора компоновки; готовый герой должен быть сопоставлен с утверждённым изображением. Сбор ассетов: [ASSETS.md](ASSETS.md).

## Проверка перед реализацией

- Пользователь принял показанные композиции или дал конкретные изменения.
- Уточнён единый набор текстов для desktop/mobile/projector.
- У каждого учебного блока записаны документ и раздел/номер задания; текст, условие и проверка ответа соответствуют источнику. Полный сценарий охватывает предусмотренные устные и бумажные части.
- Текст и кнопки проверены в реальной ширине; изображения генерации сами не доказывают читаемость HTML.
- Культурные изображения, если добавлены, подтверждены подходящими источниками.
- PDF/DOCX подготовлены отдельно; декоративные ссылки на макетах не считаются готовыми файлами.
- Вёрстка выполняется после этого этапа по Product Design image-to-code, затем проверяется в браузере.
