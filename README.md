# Альбом дружбы

Авторский образовательный сайт: уроки русского языка для 3 класса через знакомство с народами России. Планируется около 20 уроков; сейчас предоставлены материалы первых трёх. Сайт нужен учителям, ученикам и для представления авторской работы на педагогическом конкурсе.

## Текущее решение

Первая версия — статический сайт без базы данных, регистрации и серверной админки. Учебные материалы хранятся в файлах проекта. Изученные знакомства отмечаются на карте и сохраняются в браузере. Резервная копия путешествия экспортируется в файл и может быть импортирована на другом устройстве.

Визуальное направление — выбранный пользователем **«Альбом дружбы»**: светлая бумага, акварель, тёплый коричневый текст, шалфейные и терракотовые акценты. Вариант «Навстречу друг другу» не выбран.

## Три работающих урока

Реализованы подготовка учителя и полные рабочие листы Егора, Айдара и Амины. У Егора восемь заданий; у Айдара пять; у Амины пять и отдельная итоговая самооценка. Скачивания Word, режим проектора, карта с двадцатью точками, отдельные отметки, экспорт и импорт прогресса работают без регистрации. Остальные 17 уроков готовятся. Фото автора пока заменено явной заглушкой; PDF ещё не подготовлены.

Код находится в `web/`: React + TypeScript + Vite. Сборка статическая; база и сервер приложению не нужны. Рабочий Git remote: [zkhrqa/site](https://github.com/zkhrqa/site).

```sh
cd web
npm ci
npm run dev -- --port 4173
```

Проверки и production-сборка:

```sh
npm test
npm run typecheck
npm run format:check
npm run build
npm run test:sites
```

Для REG.RU в корень сайта загружается **содержимое `web/dist/client/`**. Hash-маршруты работают без настройки SPA fallback. Обычная сборка размещается в корне домена; отдельная сборка Pages учитывает подкаталог `/site/`. `dist/server/` — инфраструктура шаблона для возможного отдельного Sites-хостинга, обычному статическому хостингу она не нужна.

Карта загружается отдельным модулем, поддерживает масштаб, перемещение, группировку и список всех остановок на телефоне. Новые уроки связываются с существующими точками через реестр опубликованных материалов.

Сжатые изображения и шрифты уже находятся в `web/public/`. Пересоздание WebP и географического пути из сохранённых оригиналов: `npm run assets`, затем `npm run format`. Оригиналы документов и референсы в клиентскую сборку не включаются.

Подробности: [реализация и соответствие источникам](docs/IMPLEMENTATION.md), [визуальная проверка](design-qa.md).

## Демонстрация через GitHub Pages

Адрес черновика: [zkhrqa.github.io/site](https://zkhrqa.github.io/site/). Публикация выполняется из корня ветки `gh-pages`; в неё попадает только содержимое статической сборки `web/dist/pages/`. Основной код, документы и история работы хранятся в `main`.

После коммита и отправки исходников обновить демонстрацию можно так:

```sh
cd web
npm run deploy:pages
```

Скрипт собирает приложение с `base=/site/`, проверяет артефакты и отправляет их в `gh-pages` без переключения рабочего checkout и без принудительного push. Обновление только `main` само по себе демонстрацию не пересобирает. `npm run build:pages` выполняет только сборку, `npm run test:pages` — сборку и проверку путей. Обычная `npm run build` сохраняет совместимость с корнем домена на REG.RU и существующей упаковкой Sites.

Прогресс браузера привязан к адресу сайта: отметки из локального предпросмотра переносятся на Pages вручную через JSON-файл.
